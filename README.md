# ПромПул (Artel)

B2B-платформа технологического матчинга и промышленной кооперации для AgTech и FoodTech:
заказчики публикуют потребность в замене импортных узлов, деталей и ингредиентов, отмечают её
«звёздами» с объёмом закупки, а российские производители объединяются в кооперации, чтобы её
закрыть.

Сейчас в репозитории технический фундамент (приложение, база данных, линтер, тесты, CI),
стартовая страница поиска, каталог производителей, регистрация предприятий и личные кабинеты:
профиль, документы, свой каталог, сделки, отзывы и счётчик успешных сделок, а также режим
предприятия: ползунок «Покупателям | Продавцам» в шапке открывает рынок заказов (`/market`).
Заказчик, не нашедший позицию, размещает заказ с ТЗ, файлами и контактами (`/orders/new`), и
продвигает его звёздами; другие предприятия, которым нужно то же, тоже вкладывают звёзды и
указывают свой объём. Звёзды покупаются пакетами в кабинете (`/profile/stars`). Приём платежей
пока заглушка: оплата проходит на тестовой странице без денег, настоящий провайдер подключается
в `src/server/stars/payments.ts`.

**Онлайн-превью без установки:** приложение разворачивается на Vercel с базой Neon, и каждое
изменение в ветке обновляет ссылку. Как подключить — в разделе [Онлайн-превью](#онлайн-превью).

## Быстрый старт

Нужен только Node.js 22+. Docker не обязателен: локальную PostgreSQL запускает сам Prisma
(`prisma dev`, база хранится в папке пользователя и переживает перезапуск).

```bash
cp .env.example .env     # переменные окружения
npm install              # зависимости (+ генерация Prisma Client)
npm run db:start         # локальная PostgreSQL в фоне (порты 51213–51215)
npm run db:deploy        # применить миграции
npm run db:seed          # демо-данные: два предприятия, позиция, сделки, отзывы
npm run dev              # http://localhost:3000
```

Поиск: введите «деталь» на главной или откройте <http://localhost:3000/search?q=деталь>.
Вход в демо-аккаунты: `seller@demo.artel` (продавец «ООО Обнал»), `seller2@demo.artel`
(продавец «ООО Техмаш-Юг») и `buyer@demo.artel` (покупатель «АО Агрохолдинг «Заря»»),
пароль `artel-demo`. Или зарегистрируйте своё
предприятие на <http://localhost:3000/register>.
Проверка, что приложение видит базу: <http://localhost:3000/api/health> должен вернуть
`{"status":"ok","db":"ok"}`.

После перезагрузки компьютера достаточно снова выполнить `npm run db:start` и `npm run dev`.
Остановить базу: `npm run db:stop`.

### Windows

Команды те же, их можно выполнять в Git Bash. В PowerShell или cmd вместо `cp` используйте
`copy .env.example .env`. Если порт 51214 занят, поменяйте порты в скрипте `db:start` в
`package.json` и в `.env`.

### PostgreSQL в Docker (необязательно)

Если Docker установлен, можно использовать его вместо `db:start`: в `.env` раскомментируйте
строку `DATABASE_URL` для Docker (и закомментируйте две строки выше), затем `npm run db:up`.
Запустить всё целиком в Docker (приложение + БД):

```bash
docker compose --profile app up --build
```

### Куда добавлять новый код

По мере роста платформы предметные области стоит выделять в отдельные модули внутри
`src/server/<модуль>/` (данные и бизнес-правила) и соответствующие маршруты в `src/app/`.
Ожидаемые модули по концепции продукта:

- `auth`: регистрация, вход, сессии (есть);
- `organizations`: профили предприятий, документы, репутация (есть), верификация («Анти-Перекуп»);
- `deals`: сделки и отзывы (есть);
- `requests`: технологические запросы (Issues) и «звёзды» спроса;
- `catalog`: каталоги продукции и мощностей производителей;
- `collaborations`: производственные кооперации и консорциумы.

Тесты кладутся рядом с кодом: `файл.test.ts`.

## Каталог и поиск

### Данные

- **`Organization`** — предприятие (подробнее в разделе «Аккаунты предприятий»). Права на
  каталог идут через членство пользователя в предприятии.
- **`Product`** — позиция каталога, принадлежит организации: название, описание, цена в рублях
  (`Decimal`, с копейками), **срок производства в днях** (`leadTimeDays`), город производства и
  статус `DRAFT` → `PUBLISHED` → `ARCHIVED`. Покупатель видит не срок, а дату готовности: день
  просмотра (по Москве) плюс `leadTimeDays`. Поиск показывает только `PUBLISHED`.

Позиции читаются и пишутся только через `src/server/catalog/products.ts`: там проверка данных
(Zod-схемы в `schemas.ts`), принадлежность позиции организации и пересчёт поля `searchText`.
Страница поиска, API и сид пользуются одними и теми же функциями.

**Поиск** целиком на PostgreSQL, без внешних сервисов (`src/server/catalog/search.ts`):

- полнотекстовый индекс с русской морфологией (`searchVector`, его считает триггер базы):
  «подшипники» и «подшипника» находят «подшипник»; название и артикулы весят больше описания;
- служебные слова и слова закупщика («для», «нужен», «аналог», «ООО») не требуются в карточке;
- синонимы и английские названия (`synonyms.ts`): «сальник» находит «манжету», «bearing» —
  подшипник; набор в английской раскладке («gjlibgybr») тоже понимается;
- опечатки исправляются по словарю каталога (расстояние Левенштейна, `fuzzystrmatch`):
  «подшибник» → «подшипник», страница пишет, что исправила;
- артикулы ищутся слитно и в разных написаниях (`pg_trgm`): «6205-2RS», «6205 2rs», «62052рс»,
  а также по артикулу импортного аналога из поля «Заменяет» (`analogs`);
- если точного совпадения нет, показываются похожие позиции с пометкой и ссылкой на заказ;
- при равной релевантности выше продавцы с хорошим рейтингом, успешными сделками и
  проверенными реквизитами.

Тесты на реальных запросах — `src/server/catalog/search.db.test.ts` (`npm run test:db`),
демо-каталог для них и для сида — `prisma/demo-catalog.ts`.

Запросы, показы позиций в выдаче и просмотры карточек записываются (`SearchQuery`,
`ProductEvent`) для раздела «Аналитика» в кабинете.

Каталог заполняет производитель в режиме продавца: в личном кабинете (`/profile/products`)
или через API (см. «Аккаунты предприятий → API»).

## Аккаунты предприятий

### Данные

- **`Organization`** — предприятие: реквизиты (ИНН, ОГРН, адрес), описание, контакты, год
  основания и два режима — `isSeller` (свой каталог, входящие сделки) и `isBuyer` (предложения
  сделок по чужим позициям). Один аккаунт может и продавать, и покупать. `verifiedAt` —
  отметка о проверке реквизитов, пока ставится вручную в базе.
- **`User`** — человек, который входит на сайт (email, имя, scrypt-хэш пароля).
- **`Membership`** — связь пользователя с предприятием и роль (`OWNER`, `MEMBER`). Сейчас при
  регистрации создаётся владелец; приглашение сотрудников — следующий шаг.
- **`Session`** — сессия входа: в httpOnly-cookie `artel_session` случайный токен, в базе —
  только его SHA-256. Срок 30 дней, выход удаляет запись.
- **`OrganizationDocument`** — документ или отчёт: тип (регистрационные, сертификаты, лицензии,
  финансовая отчётность, качество, прочее), номер, даты выдачи и окончания, ссылка на файл,
  видимость на публичной странице. Загрузка файлов на платформу — следующим шагом.
- **`Deal`** — сделка между предприятиями по позиции каталога: покупатель предлагает
  (`REQUESTED`), продавец принимает (`ACCEPTED`), покупатель подтверждает получение
  (`COMPLETED`), любая сторона может отменить до завершения (`CANCELLED`). Правила хода — в
  `src/server/deals/transitions.ts`. Название и цена копируются в сделку на момент предложения.
- **`Review`** — отзыв (оценка 1–5 и текст) только по завершённой сделке, по одному от каждой
  стороны. Поэтому отзывы и счётчик успешных сделок нельзя накрутить без сделки на платформе.

### Страницы

| Адрес                 | Что там                                                             |
| --------------------- | ------------------------------------------------------------------- |
| `/register`, `/login` | Регистрация предприятия вместе с контактным лицом, вход             |
| `/profile`            | Обзор: успешные сделки, рейтинг, что ждёт действия, что дозаполнить |
| `/profile/company`    | Профиль предприятия и режимы продавца/покупателя                    |
| `/profile/documents`  | Документы и отчёты, видимость для всех                              |
| `/profile/products`   | Свой каталог: добавить, изменить, опубликовать, снять с продажи     |
| `/profile/deals`      | Сделки, где продаём и где покупаем, кнопки хода сделки, отзывы      |
| `/profile/reviews`    | Отзывы о нас и наши отзывы                                          |
| `/profile/analytics`  | Место под аналитику (раздел в разработке)                           |
| `/companies/{id}`     | Публичная страница: репутация, реквизиты, каталог, документы        |
| `/products/{id}`      | Позиция; вошедший покупатель предлагает сделку                      |

Страницы кабинета читают сессию внутри `<Suspense>` (так требует Cache Components) и каждый
раз проверяют её на сервере через `requireOrganizationUser`. Server Actions в
`src/app/profile/actions.ts` тоже заново проверяют сессию, а не доверяют странице.

### API

Запись защищена сессией: пользователь должен состоять в предприятии из адреса, а для позиций
каталога у предприятия должен быть включён режим продавца. Без входа — 401, чужое предприятие
или выключенный режим — 403.

| Метод и адрес                                      | Что делает                                         |
| -------------------------------------------------- | -------------------------------------------------- |
| `POST /api/auth/login`                             | Вход по `{ email, password }`, ставит cookie       |
| `POST /api/auth/logout`                            | Выход                                              |
| `GET /api/auth/me`                                 | Кто вошёл и его предприятие                        |
| `GET /api/products/search?q=…`                     | Поиск покупателя (без входа)                       |
| `POST /api/organizations`                          | Создать ещё одно предприятие, стать его владельцем |
| `GET /api/organizations/{id}`                      | Публичный профиль и репутация (без входа)          |
| `PATCH /api/organizations/{id}`                    | Изменить профиль                                   |
| `GET /api/organizations/{id}/products`             | Все позиции предприятия, включая черновики         |
| `POST /api/organizations/{id}/products`            | Добавить позицию (по умолчанию черновик)           |
| `GET`/`PATCH /api/organizations/{id}/products/{p}` | Позиция; правка полей, публикация, архив           |

Пример с демо-аккаунтом:

```bash
curl -s -c jar -X POST localhost:3000/api/auth/login \
  -d '{"email":"seller@demo.artel","password":"artel-demo"}'
ORG=$(curl -s -b jar localhost:3000/api/auth/me | jq -r .organization.id)
curl -s -b jar -X POST localhost:3000/api/organizations/$ORG/products \
  -d '{"name":"Насос шестерённый","price":"25000.50","leadTimeDays":14,"city":"Тула","status":"PUBLISHED"}'
```

Поля позиции: `name`, `description`, `price` (число или строка, до 2 знаков после точки),
`leadTimeDays` (целое число дней, неделя = 7), `city`, `status`. Ошибки проверки возвращаются
с кодом 400 и описанием по полям, чужая или несуществующая позиция — 404.

## Онлайн-превью

Чтобы смотреть результат без Docker и без установки, приложение собирается на
[Vercel](https://vercel.com) с бесплатной PostgreSQL от [Neon](https://neon.tech). После
подключения каждый push в любую ветку даёт свою ссылку, а у каждой ветки есть постоянный
адрес вида `https://<проект>-git-<ветка>-<аккаунт>.vercel.app`, который обновляется сам.

Подключение (один раз, всё в браузере):

1. Войти на [vercel.com](https://vercel.com/signup) через GitHub.
2. **Add New → Project**, выбрать репозиторий `Artel`, нажать **Deploy** (первая сборка упадёт
   без базы — это нормально).
3. В проекте: **Storage → Create Database → Neon** (бесплатный план), подключить ко всем
   окружениям (Production, Preview, Development). Vercel сам добавит `DATABASE_URL` и
   `DATABASE_URL_UNPOOLED`.
4. **Deployments → Redeploy**.

При каждой сборке `npm run vercel-build` применяет миграции (`prisma migrate deploy`),
обновляет демо-данные (`prisma db seed`, повторный запуск безопасен) и собирает приложение
(см. `vercel.json`). В превью работают демо-аккаунты из раздела «Быстрый старт».

## Хостинг на Amvera

[Amvera Cloud](https://amvera.ru) — российский хостинг, сайт открывается из РФ без VPN. Проект
собирается по `Dockerfile` (настройки в `amvera.yml`, порт 3000). Переменные окружения Amvera
не передаёт в сборку, поэтому база нужна только при старте: `scripts/docker-start.sh` применяет
миграции, обновляет демо-данные (повторный запуск безопасен) и запускает сервер. Шаги
отключаются переменными `MIGRATE_ON_START=0` и `SEED_ON_START=0`.

Тариф: хватает **«Начальный Плюс»** (0,5 CPU, 1 ГБ, около 16 ₽ в сутки); сервер занимает около
200 МБ памяти. На «Начальном» (0,25 CPU) сайт тоже работает, но страницы открываются медленнее.

Подключение (всё в браузере):

1. Зарегистрироваться на [amvera.ru](https://amvera.ru) и пополнить баланс (на 2–3 дня хватит
   100 ₽).
2. **Создать проект** → тип «Приложение», имя (например, `artel`), тариф «Начальный Плюс».
   Окружение Amvera определит само по `amvera.yml` (Docker).
3. Вкладка **«Репозиторий»** → GitHub: событие Push, придумать секрет, целевая ветка `main`,
   скопировать адрес и нажать **«Применить»**. В GitHub: репозиторий → Settings → Webhooks → Add
   webhook, вставить адрес, Content type `application/json`, тот же секрет, **Add webhook**. Для
   приватного репозитория Amvera попросит classic-токен GitHub с правом `repo`.
4. Вкладка **«Переменные»** → «Добавить переменные или секрет» (лучше как секрет):
   - `DATABASE_URL` — строка подключения к PostgreSQL;
   - `DATABASE_URL_UNPOOLED` — только для Neon: прямой адрес для миграций.

   Проще всего взять ту же базу Neon, что у превью на Vercel: Vercel → проект → **Storage** →
   база Neon → вкладка `.env.local` → **Show secret**, скопировать оба значения. Если Neon из
   Amvera недоступен или медленный, создайте в Amvera **PostgreSQL** (тот же тариф) и укажите
   `DATABASE_URL=postgresql://<пользователь>:<пароль>@cnpg-<имя-проекта-бд>-rw:5432/<база>`;
   `DATABASE_URL_UNPOOLED` тогда не нужен.

5. Сделать любой push в `main` (или в Amvera **«Пересобрать»**). Сборка идёт 5–10 минут, лог —
   во вкладке «Лог сборки», запуск и миграции — в «Лог приложения».
6. Вкладка **«Домены»** → «Добавить доменное имя» → «Бесплатный домен Амвера». Адрес вида
   `https://artel.<аккаунт>.<регион>.amvera.tech` можно отправлять. Работают демо-аккаунты из
   «Быстрого старта».

Чтобы не платить после показа, проект в Amvera можно остановить или удалить.
